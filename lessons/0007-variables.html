配置期 ${VAR} 与呼叫期 {{var}}

约 3 分钟。本课只记一件事：Playbook 里有两种变量写法，不要混用。${VAR} 在加载 YAML 前置时按环境变量替换；{{var}} 在呼叫对话时按运行时变量替换。下面是摘录，不能直接运行。本课只读文件。

配置期这一行同时出现在 模板句法对照 和 env_vars_example.md。呼叫期的两个名字是该提交源码注入的内置量，单元测试写成带空格的 {{ session_id }}、{{ call_type }}。拼在一起只为对照时机，不是仓库里的一份现成文件。

摘录（不完整，不可直接运行）

---
llm:
  model: "${LLM_MODEL}"
---

# Scene: main
会话：{{ session_id }}
类型：{{ call_type }}

${LLM_MODEL} 属于 YAML 前置。该提交的 Playbook::parse 只对这对 --- 之间的 YAML 调用 expand_env_vars；环境变量没有设置时，源码把 ${VAR} 原文留下。句法对照还写「正文里的 ${VAR} 会在加载时变成固定值」；本课读到的解析函数没有对正文做这一步，所以正文那一句不下结论。

{{ session_id }} 和 {{ call_type }} 属于正文。通话对象创建时把这两个名字写进会话变量；场景提示在渲染时用 MiniJinja 替换。call_type 在源码里是 sip、websocket、webrtc 或 b2bua 之一。这不是主配置 active-call.toml 的替换规则，本课也不把它推广到所有字段。

同一次提交的文档并不一致，本课不选边。句法对照把带连字符的 SIP 头写成 {{X-Customer-Name}}，字段名用 extract_headers。高级特性文档和 src/playbook/mod.rs 的测试写成 {{ sip["X-Customer-Name"] }}，并说明连字符会被 Jinja 当成减法。教程示例的字段名是 extractHeaders，而 SipOption 的字段是 extract_headers，没有驼峰重命名。练习不用这种名字。不要读取或填写真实密钥。本课不调用模型、不发起呼叫。

练习

先不要往下看。在上面的摘录里，${LLM_MODEL} 和 {{ session_id }} 各属于哪一种变量？哪一个在加载 YAML 时按环境变量替换，哪一个在呼叫对话时替换？

先答完再展开

${LLM_MODEL} 是配置期环境变量，在加载 YAML 前置时替换。{{ session_id }} 是呼叫期运行时变量，在对话渲染时替换。不要把这两种写法混用。本课只读文件，未运行。

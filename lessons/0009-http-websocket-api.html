先分清通话入口和控制接口

约 3 分钟。本课只记一件事：有的路径用来接通话，有的路径用来查询或控制已经存在的通话。不要把这两类混成一件事。本课只读文档和路由，不发送任何请求。

对照固定提交的 docs/api.md，并用 call_router 核对注册方式。文档把前三条放在「WebSocket Call Endpoints」，把 /list、/kill/{id} 放在「REST API Endpoints」。源码里这五条都注册为 GET。前三条的处理函数接收 WebSocket 升级；后两条不接收升级，只读通话表或取消指定会话。

摘录（不完整，只列路径，不可当作可执行命令）

GET /call
GET /call/webrtc
GET /call/sip

GET /list
GET /kill/{id}

路径取自文档的端点行，方法与该提交的路由一致。官方样例里还有指向本机的调用写法，本课不抄，以免被误发送。

前三条是通话入口，升级之后音频走的路不同：/call 经 WebSocket 传音频，/call/webrtc 走 WebRTC，/call/sip 把通话类型标成 SIP，音频走 SIP/RTP。这里的 HTTP 是注册路径的方法；WebSocket 是通话入口要求的升级。二者不是同一层，不能互相代替。/call/sip 不是第 4 课的 SIP UDP 端口，也不是第 3 课的呼入 Webhook 处理器。

后两条是控制或查询：/list 返回当前活动通话的 JSON，/kill/{id} 按路径里的会话 ID 取消该通话。文档里还有命令、事件流、Playbook 和记录等路径，本课不展开。

Authentication 只写：多数端点需要 WebSocket 升级才能做实时通信。这句话说的是升级，不是令牌或登录。该提交的路由没有给这些处理函数加令牌参数，文档也没有描述 REST 令牌。样例里没有 token，不能当成已经安全，也不能当成「没有别的访问控制」的证明。控制接口不要对公网开放。本课不发起通话、不终止通话、不调用付费接口。

练习

先不要往下看。/call/webrtc 和 /list 各属于哪一类：通话入口，还是控制/查询接口？请再指出摘录里哪一条是用来终止通话的。只根据文档和上面的路径作答，不要发送请求。

先答完再展开

/call/webrtc 是通话入口。/list 是控制/查询接口，用来列出活动通话。用来终止通话的是 /kill/{id}。本课只读材料，未发送任何请求。

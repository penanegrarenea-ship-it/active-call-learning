两种呼入处理器：Playbook 与 Webhook

约 3 分钟。本课只记一件事：入口管怎么接进来，处理器管接进来之后按什么逻辑处理。本课不写代码、无需安装，对照尚未运行。

上一课对照的是三种入口：音频从浏览器、SIP 设备还是自己的程序送来。入口选好以后，还要决定来话按什么逻辑处理。这两层不是一回事。

它是什么怎么记
Playbook 本地的 Markdown 文件 用 YAML 前置声明配置，用正文写场景和提示词。来话按这份稿走。
Webhook 处理器 外部的 HTTP 服务 配置指南写的是：把呼入请求转到这个服务，由它决定如何处理。

不要和另一件事混在一起：Playbook 进行中也可以用 HTTP 工具去问业务接口。官方示例 webhook_example.md 就是这类场景稿，它不是呼入 Webhook 处理器。

已读的官方文档没有写清：外部服务会不会接手整段语音处理，会不会把每段音频都经 HTTP 发出，以及它应返回什么。配置指南把这两种处理器写在「呼入处理配置」一节，开篇说明这是两种 SIP 呼入处理方式；它们是否同样用于另外两条入口，也未写清。以上均待核实。本课不把这些写成已知事实，也不展开接口字段或鉴权。

两个对照情景

  1. 想在本机放一份场景稿，写好欢迎和简单问答。这时用 Playbook。
  2. 已经有一套外部系统，希望来话先交给它，再决定怎么处理。这时用 Webhook 处理器。

练习

先不要往下看。实验环境里已经可以用 SIP 分机打进来。你想先用一份本地的欢迎场景稿来处理来话，暂时不接到外部系统。这时该选哪一种处理器？它和「选 SIP 入口」是同一件事吗？请说明理由。

先答完再展开

选 Playbook，因为处理逻辑写在本地场景稿里，还没有要交给外部 HTTP 服务去决定。选 SIP 入口只说明声音从分机或实验 PBX 进来；选处理器是进来之后按什么逻辑处理。这两件事不是同一层。本课不运行、不拨真实号码。

配置与端口：先分清 HTTP 和 SIP 监听

约 3 分钟。本课只记一件事：网页和 API 走 HTTP 监听，SIP 信令走 UDP 监听；端口以你正在用的配置为准，不能照抄另一份文档。下面是摘录对照，本课未运行、无需安装。

先看同一提交里的两处写法，数字并不一样。

来自 active-call.example.toml：

http_addr = "0.0.0.0:8080"
udp_port = 13050

来自 中文配置指南的基础配置示例（文中还写 UDP「默认 25060」）：

http_addr = "0.0.0.0:8080"
udp_port = 25060

同提交里还有：Dockerfile 暴露 8080 和 13050/udp；同一份配置指南的 FAQ 防火墙示例写 HTTP 8080、SIP 13050；Twilio 指南示例则是 udp_port = 5060、tls_port = 5061。不要把这些合成一个官方默认端口。

字段本身是清楚的（以配置指南的说明为准）：

  • http_addr：HTTP 服务的完整地址（IP + 端口），网页客户端和 API 都走这里。
  • addr：SIP 服务绑定的 IP。
  • udp_port：UDP 端口，用于 SIP 信令；指南还写它也用于 RTP 媒体。另有 rtp_start_port / rtp_end_port 范围，本课不展开。

命令行的 --http、--sip 可以覆盖文件里的值。无论看哪份文档，都以你正在用的那份配置和实际启动参数为准。

官方示例里 [recording] enabled 与 auto_start 默认是 true。课堂片段要先关掉，而且只是摘录，并未运行。HTTP 端口还是控制面（如查询、结束通话、读写 Playbook）；API 文档的 Authentication 只写多数端点需要 WebSocket 升级，未描述 REST 令牌鉴权。不能因为示例没写 token 就当成已鉴权，也不要把这个端口对公网开放。

课堂片段（未运行，不是官方默认文件）。端口数字跟自 active-call.example.toml；录音已关闭；http_addr 收到本机，仅为课堂收紧，官方示例常见 0.0.0.0:8080。

http_addr = "127.0.0.1:8080"
udp_port = 13050

[recording]
enabled = false
auto_start = false

练习

先不要往下看。你正在用的配置文件里写着 http_addr = "127.0.0.1:8080"、udp_port = 13050。同事按中文配置指南说 SIP 端口是 25060。要把实验 PBX 对上这条 SIP 入口，该填哪个端口？若只是打开本机网页或调用 HTTP API，又该连哪一个？请说明理由。

先答完再展开

SIP 入口填 13050，因为以正在用的配置为准，不能照抄指南里的 25060。网页和 HTTP API 走 http_addr，也就是 127.0.0.1:8080。这两个端口不是一回事。本课未运行，也不对接真实电话网。

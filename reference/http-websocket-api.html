通话入口与控制接口

供以后重开。对照官方 docs/api.md 和该提交的路由。不是官方文档，也不表示已经掌握，也尚未发送任何请求。

  • 通话入口：GET /call、GET /call/webrtc、GET /call/sip。处理函数接收 WebSocket 升级。升级之后音频分别走 WebSocket、WebRTC、SIP/RTP。
  • 控制/查询：GET /list 返回活动通话 JSON；GET /kill/{id} 按会话 ID 取消通话。这两个处理函数不接收 WebSocket 升级。
  • /call/sip 不是 SIP UDP 端口，也不是呼入 Webhook 处理器。HTTP 方法与 WebSocket 升级不是同一层。
  • Authentication 只写多数端点需要 WebSocket 升级。那不是令牌鉴权。样例无 token，不能当成已经安全，也不能当成没有别的访问控制。
